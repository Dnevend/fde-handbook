# 运维手册（Runbook）

> 面向值班人员：出问题时先做什么、看哪里、什么时候升级。  
> 不要把“重启试试”写成第一步；先保留现场。

## 1. 启停

```bash
# 启动
bash run.sh
# 或 systemctl start 【service】

# 停止
bash stop.sh
# 或 systemctl stop 【service】

# 状态
curl -s http://127.0.0.1:8090/health
```

## 2. 健康检查

| 检查 | 命令 | 正常 | 异常先看 |
|---|---|---|---|
| 服务 | `curl /health` | 200，chunks>0 | 服务日志、端口 |
| 模型 | `curl http://127.0.0.1:8080/health` | 200 | 模型路径、显存 |
| 索引 | `/health` 的 chunks | 与语料一致 | `.cache/`、权限 |
| 指标 | `curl /metrics` | `rag_requests_total` 增长 | 进程是否重启 |
| 磁盘 | `df -h` | 使用率 < 【阈值】 | 日志/反馈/索引 |
| GPU | `nvidia-smi` | 温度/功耗正常 | 降频、其他进程 |

## 3. 日志与追踪

- JSON 日志：【路径】；按 `request_id` 搜索。
- traces：`benchmarks/delivery/traces.jsonl`；按用户/耗时筛。
- audit：`benchmarks/delivery/audit.jsonl`；权限相关。
- 指标：`/metrics`；Prometheus 【地址】。

**排障顺序**：`request_id` → 日志 span → traces → metrics → 系统/GPU。不要先改配置。

## 4. 常见告警

| 告警 | 可能原因 | 处理 |
|---|---|---|
| 5xx 升高 | 模型服务挂了/显存不足 | 看服务日志、`nvidia-smi`；必要时回滚 |
| TTFT p95 升高 | 队列/长 prompt/降频 | 看队列、prompt 分布、throttle reasons |
| 错误率升高 | 上游/网络/权限策略 | 看网关、audit、依赖健康 |
| 磁盘满 | 日志/反馈/追踪未轮转 | 清理/轮转；保留审计 |
| 无引用回答增多 | 检索空/权限过滤/模型跑偏 | 看 traces 的 docs、检索命中率 |

## 5. 备份与恢复

- 备份对象：配置、索引、语料清单、权限策略、审计（按保留期）。
- 频率：【每日/每周】；保留：【天数】；存放：【路径/对象存储】。
- 恢复演练：【日期】；恢复后必须重跑 `/health` + 已知问题。
- 模型权重可重新获取的，备份清单/哈希即可；不能重新获取的，按客户要求备份。

## 6. 升级

1. 读变更记录，确认影响面。
2. 备份配置/索引/策略。
3. 在预发环境跑验收用例（至少：已知问题、拒答、权限、离线）。
4. 灰度/停机窗口切换。
5. 观察 30 分钟指标；异常回滚。
6. 更新版本记录和交付包。

## 7. 故障处理

| 现象 | 先做 | 不要做 |
|---|---|---|
| 服务起不来 | 看启动日志第一条 ERROR | 反复重启 |
| OOM | 记录 `nvidia-smi`/日志，降并发/上下文 | 直接加卡 |
| 回答变慢 | 看 TTFT/TPOT/队列/降频 | 先改提示词 |
| 权限异常 | 看 audit/策略版本 | 关掉权限过滤 |
| 数据泄漏怀疑 | 保留日志/审计，按事件流程上报 | 删除日志 |
