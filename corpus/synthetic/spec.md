# 合成语料的规则

真实语料只够做"对不对"，不够做"规模、权限、冲突"。合成件补这三类，原则是一句话：

> **骨架用真的，表壳用真的，数值用真的，只有填进去的那格是生成的。**

凭空编一份"注塑机手册"没有价值——它的章节顺序、字段名、单位、层级都是外行想象出来的，切分和表格抽取在它身上跑出来的结论无法迁移到真文档。所以合成不是"写文档"，是**拼装**。

## 四层拼装

| 层 | 来源 | 提供什么 |
|---|---|---|
| 骨架 | `ipo-*`、`eia-injection-01` | 章节顺序、段落长度、叙述口吻、设备族 |
| 表壳 | `synthetic/fields.yaml`（字段逐字取自 `gov-ledger-guide` 的台账范本） | 表头字段名、单位、签字栏 |
| 数值 | `pat-inj-01/02` | 料温、模温、注射压力、保压时间、冷却时间、周期 |
| 空缺 | 生成模型 | 工单号、日期、人名、实测偏差、异常描述 |

字段名不许自创。凡是"检查结果 / 备注"这类万能列，都说明表壳没取自真实模板，回上一步重取。

`fields.yaml` 里每张表都标了 `provenance`：`verbatim` 是逐字抄的政府范本，`derived` 是按台账字段组合推导的。日常点检表属于后者——北京市那份工作指南里没有逐日用点检表，别声称它抄自政府文件。

## 各类型的量

| 类型 | 份数 | 服务章节 | 备注 |
|---|---|---|---|
| 工艺参数卡 | 20 | 5.3, 5.8 | 表头来自真实参数表；数值取自专利实施例区间 |
| 设备点检表 | 15 | 5.2, 5.3 | 表壳来自政府检查清单；含"漏项"变体 |
| 保养计划 | 8 | 5.9 | 按 150k / 300k 模次分档，制造版本差异 |
| 维修工单 | 10 | 5.9, 6.5 | 现象—原因—处理三段式；含一次"记录了但没闭环" |
| 换模记录 | 5 | 5.6 | 同模具多次换机的参数漂移，用于混合检索 |
| 质量异常单 | 2 | 6.3 | 与点检表、工单交叉引用，造多跳题 |

合计 60 份，约 100–300 MB 文本（与真实语料合计撑到 2000 页级别）。

## 必须造进去的四种"脏"

1. **版本冲突**：同一台注塑机的两份保养计划，换油周期一个 2000 h、一个 3000 h，后者日期更新但没有修订说明。
2. **术语不一致**：同一部件在目录叫"射台"、正文叫"注射座"、报警表叫"料筒座"。
3. **权限分层**：`dept`（注塑 / 模具 / 设备 / 质量）× `level`（公开 / 内部 / 受限），至少一份受限文档与公开文档讲同一个参数但取值不同。
4. **过时条款**：引用已废止的旧版规程编号，且文中没有任何标记。

四个"脏"不是装饰，是 5.6、5.9、6.5 的实验对象。没有它们，那三节的结论只能靠嘴说。

## 落地

规则由 `generate.py` 实现，四类"脏"各有固定的定位点，改动生成器时别把它们弄丢：

| 脏 | 定位 | 验证 |
|---|---|---|
| 版本冲突 | `MP-001` / `MP-002`（同机 ZJ-01，周期 2000 h / 3000 h，版本 A/0 → A/1 无修订说明） | `grep ZJ-01 maintenance_plan/*.md` |
| 术语不一致 | `PC-*` 写"射台"，`DI-*` 写"注射座"，`RO-*` 写"料筒座" | `INJECTION_UNIT` 常量 |
| 权限分层 | `PC-007` 是 `PC-001` 的受控变体，只有模温高 10℃ | 两份对比数据行 |
| 过时条款 | `RO-003` 引用 `QG-2016-07（已废止）` | `grep 已废止` |
| 漏项 | `DI-005` 缺"安全门"这一行 | `grep -c 安全门` 应为 0 |

改完生成器先跑 `uv run corpus/synthetic/generate.py --clean --validate`：它会逐项验上面五行，外加份数、字段声明和同 seed 的确定性。缺一项就报错，不让人靠记忆维护。

## 元数据

每份合成件头部带一个注释块：

```yaml
# synthetic: true
# generator: <model>@<date>
# prompt_sha256: <hash>
# base_template: ipo-hitech | eia-injection-01 | gov-checklist-hs
# seed: <int>
```

`base_template` 必填——读者要能顺着它找到"这份东西是照谁的样子造的"。

## 一条硬规则

合成语料只能用于**规模、权限、冲突、脏数据**四类实验。凡是正文里标"实测"的结论，必须跑在真实语料上。反过来，合成件上跑出来的数字不许写成实测。

这条不写死，整本书会被一句"你的语料是编的"打掉。

## 扫描件

扫描件的难点是退化过程，不是内容。所以用**可入库的真实文本**（法规、政府清单、专利）渲染成 PDF → 打印 → 扫描，得到内容合法、退化真实的扫描件，可以入库。

- 真机扫描 3 份，留作对照（倾斜、印章压字、装订线阴影）；
- 其余用 Augraphy（MIT）批量退化：折痕、污渍、复印噪点、JPEG 二次压缩。

退化参数记在文件名里（如 `__scan-seed42.jpg`），保证可复现。
