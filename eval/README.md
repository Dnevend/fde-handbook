# 测试集（第五、六部分共用）

`qa.jsonl` 是 80 道中文题，用于第五部分的检索与生成实验，也是第六部分扩题的起点。
每行一题，字段如下：

| 字段 | 含义 |
|---|---|
| `id` | `D`（直接摘取）/`C`（条件判断）/`X`（跨段组合）/`R`（拒答）+ 两位序号 |
| `category` | `direct` / `condition` / `cross` / `refuse` |
| `question` | 问题。改写过，不抄条款原文，避免关键词检索白捡 |
| `answer` | 标准答案，用于判定（不是给模型看的） |
| `sources` | 出处：`doc` 是语料 id，`clause` 是条款号。拒答题为空 |
| `synthetic` | 出处是否来自合成语料；本集全部为 `false` |
| `joint` | 跨段题是否需要两个出处都命中才算成功 |

## 四类怎么分

- **直接摘取（20）**：答案在一段话里，问法换过。
- **条件判断（20）**：给一个场景（人数、金额、行业），要套用条款里的阈值或适用范围。
- **跨段组合（20）**：答案分散在两条条款，必须两段都找到（`joint: true`）。
- **拒答（20）**：语料里没有答案，正确行为是说「资料中没有相关信息」。

## 出题口径

1. 题目从 `corpus/index.json` 的条款出发，人工挑题、改写成自然问法；答案回到条款原文核对。
2. 拒答题覆盖财务、人员、客户、工艺配方、设备参数等语料明确没有的类别。
3. 不写「第 X 条怎么规定」这类题——那是在考关键词，不是在考检索。
4. 出处必须能落到 `(doc, clause)`；`validate.py` 会去 `corpus/index.json` 核对。

## 规模与局限

- 80 题只能分辨 10 个百分点以上的差异（二项比例区间约 ±10pp）；要分辨 3–5 个点，需要 300 题以上（见 4.6 的讨论）。
- 题目全部来自真实语料（法规、政府文件），不覆盖事故报告与专利；那些语料只做链路演示。
- 同一题的标准答案可能被多条相邻条款支持，`sources` 只记主要出处，指标因此偏保守。

## 校验

```bash
python3 eval/validate.py
```

零依赖。会检查字段、四类配额、出处存在性与条款号、cross 题的出处数量、题目重复。
